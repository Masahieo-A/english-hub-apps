# Question Time 要件定義（略案）

> 生徒が書いた essay から追随質問を作り、A4縦1枚の解答用紙・採点シート・返却シートとして印刷する教員用ツール。

## 1. 目的
- 生徒が essay を「自分のものとして説明できるか」を、授業内の短い口頭・筆記の質問で確かめる。
- 質問づくり・用紙づくりの手間を減らす。AIは質問案づくりだけに使い、判断は教員が行う。

## 2. 使う人
- 英語科教員（操作はすべて教員）。生徒は紙に答えるだけで、アプリには触れない。

## 3. 主な機能
**必須**
- 生徒の essay 一覧（クラス・番号・氏名・本文）の読み込み（.xlsx／CSV）。
- 質問づくり用の依頼文を作る機能（コピーして外部のAIチャットに渡す）。AIへ渡すのは **ID と本文だけ**。
- AIの出力表（TSV）を貼り付けて読み込む機能。1人あたり3問（Q1「どっち型」、Q2「なぜ型」、Q3「もしも型」）。
- 点検：質問が引用している箇所が essay に一字一句あるか、語数などを自動チェックし、問題があれば赤く表示。
- 印刷：解答用紙（essay全文＋質問箇所に下線と問番号）／採点シート／返却シート。A4縦1枚。
- 直したい所は画面上で編集でき、点検・プレビュー・印刷に反映される。

**あれば便利**
- 提出しなかった生徒用に、サンプル essay から氏名欄が空白の用紙を作る。
- 作業の途中保存（essay・修正済みの質問・課題設定を1つのExcelにまとめて保存し、次回続きから）。
- 1人ずつ「前へ・次へ」で用紙を確認するプレビュー。

## 4. 画面の流れ
1. 課題情報（課題名・実施日・トピック・目標レベル）を入力する。
2. essay の表（.xlsx）を読み込む。
3. 「依頼文をコピー」し、AIチャットに5人ずつ貼り付ける（氏名なし）。
4. AIが出した表をコピーして、質問の欄に貼り付ける。
5. 点検結果を見て、赤い箇所を編集して直す。
6. プレビューで1人ずつ確認し、解答用紙・採点シート・返却シートを印刷する。

## 5. 扱うデータ
- 入力（essay表）：`クラス, 番号, 氏名, essay`。IDは `クラス-番号2桁`（例 2A-01）。重複提出は最後の行を採用。
- AI出力（質問表）：`ID, 主張, 理由` ＋ 質問ごとの `引用, 質問, 和訳, 意図, 採点の論点, A例, B例`（Q1〜Q3）。
- 出力：印刷用HTML（A4）、保存用の .xlsx（essay・質問・設定の3シート）。

## 6. 個人情報の扱い
- ファイルは**ブラウザ内だけで処理**し、アプリ自体は通信しない構成を推奨（サーバー・DB・ログイン不要）。
- 外部AIへ渡すのは **ID と essay 本文のみ。氏名・クラスは渡さない**。氏名との結び付けは手元のファイル上でIDで行う。
- 編集内容はブラウザの localStorage に保存（共有PCでは作業後に消す）。保存用 .xlsx には氏名が入るため、保管場所に注意する。
- 質問は授業内・紙・辞書やAIなしで答えさせる運用にする。

## 7. 技術の例
- 例：**HTML＋CSS＋JavaScript の静的ページ**（ビルド不要）。表の読み書きは SheetJS などのライブラリで行う。
- AIは自前のAPIを呼ばず、教員が使っているAIチャットの「カスタム指示」にシステムプロンプトを貼って使う。これならAPIキーも従量課金も不要。
- 印刷は A4・余白なし・倍率100%・背景のグラフィックONで確認する。

## 8. AIに作らせるときのコツ
- 先に質問の型（どっち型→なぜ型→もしも型）、語数や語彙の制限、引用は一字一句、という**ルールを文章で固定**してから作らせる。
- サンプルの essay 表（架空の生徒4人）を作らせると、点検機能のテストがしやすい。
- 印刷レイアウトは、1画面ずつ「画面で確認→印刷プレビューで確認」と依頼する。
