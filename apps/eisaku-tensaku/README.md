# 英作文 文法添削 要件定義（略案）

> 生徒が書いた英作文を、AIが文法の観点だけで見て「ヒント」だけを返す（書き直した答えは出さない）Webアプリ。

## 1. 目的
- 生徒が自分の英文の誤りに気づき、**自力で直せる**ようになること。
- 教員の添削負担を減らすこと。AIは「正解の英文」を渡さず、ヒントに徹する。

## 2. 使う人
- 主な利用者：高校生（英語学習者。CEFR A1〜A2程度を想定）。
- 管理・改善する人：英語科教員（ログインや管理画面は不要。URLを共有するだけ）。

## 3. 主な機能
**必須**
- お題（テーマ）、必要語数、英作文本文の入力欄。本文は語数をリアルタイム表示する。
- 必要語数は「80」（最低語数）または「80-100」（範囲）の2形式のみ受け付ける。
- 語数が極端に少ない英文は送信できない（目安：20語未満、または必要語数の65%未満）。画面側とサーバー側の**二重チェック**。
- AIによる文法評価。結果は「良い点」「語数条件の充足」「文法ヒント一覧」。
- ヒントは3段階（Level 1：どこかに誤りがある／Level 2：誤りの種類／Level 3：直し方の方向性）。生徒が順に開く。
- **英文の丸ごとの書き直しは出さない**。点数も出さない。
- 評価するのは文法だけで、内容・構成は対象外と画面に明記する。

**あれば便利**
- 結果画面で、自分の英文とヒントを並べて表示し、その場で修正して再提出できる。
- 生徒の入力がAIへの命令文（「以前の指示を無視して…」等）になっていないかのチェック。

## 4. 画面の流れ
1. 入力画面：お題・必要語数・英作文を入力する。
2. 「送信」を押す。語数が足りなければ赤字でメッセージを出し、送信しない。
3. 「添削中…」のローディング表示（ボタンは無効化）。
4. 結果画面：提出した英文（折りたたみ）→ 結果サマリー → 良い点 → ヒント一覧を表示する。
5. 「もう一度添削する」で入力画面に戻り、直した英文を再提出する。

## 5. 扱うデータ
- 入力：お題（500字以内）、必要語数（文字列）、英作文本文（テキスト）。
- 出力（AIの返答はJSONで受け取る）：
  - `wordCountOk`（true/false）
  - `goodPoints`（文字列の配列）
  - `hints`（配列。各要素は `{ sentence, level1, level2, level3 }`）
- ファイル保存はしない。結果は画面の遷移用にブラウザの一時領域（sessionStorage）で受け渡す程度にとどめる。

## 6. 個人情報の扱い
- **氏名・クラス・番号の入力欄を作らない**。AIに送るのは「お題・必要語数・英文」だけにする（推奨）。
- 英文の中に自分の名前や学校名を書かないよう、入力欄の近くに注意書きを出す。
- 保存先：サーバー側にデータベースを持たない。履歴を残す場合も生徒のブラウザ内だけにする。
- AIに送る：英文本文とお題。送らない：氏名・出席番号・成績。

## 7. 技術の例
- 例：Next.js（App Router）＋TypeScript＋Vercel。
- AIは Gemini API の軽量モデル（Flash系）など、安価なもので足りる。
- **APIキーはサーバー側の環境変数に置く**（ブラウザのコードに書かない）。AIを呼ぶのはサーバー側のAPIルートだけにする。
- 失敗時の自動リトライは入れない（課金の暴走防止）。利用上限や1回あたりの入力文字数制限を設ける。

## 8. AIに作らせるときのコツ
- 「ヒントのみ。正解の英文は絶対に出さない」を、最初にプロンプト（システム指示）として明文化させる。
- AIの出力形式（JSON）を先に決めて渡す。画面の表示部分と、AI呼び出し部分を分けて作らせる。
- まず画面だけ、次に語数ガード、最後にAI連携、の順で段階的に頼むと失敗が少ない。
