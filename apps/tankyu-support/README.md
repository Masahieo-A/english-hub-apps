# 探究サポート（探究ファシリテーターAI） 要件定義（略案）

> 高校生が「探究の時間」のテーマと問いを立てるのを、AIとの対話で伴走するアプリ。答えは教えず、問いを引き出す。

## 1. 目的
- 生徒が地域探究の**テーマと問いを自力で立てられる**ようにする。
- 教員が1人ずつ付き添えない場面を、AIメンターが補う。

## 2. 使う人
- 生徒（高校2年生想定。スマホ・PC両対応）。
- 教員：URLを共有するだけ。管理画面やログインは不要。

## 3. 主な機能
**必須**
- AIチャット（4ステップで進行）：
  1. テーマ選び（X軸）：9分野（福祉・健康・労働・教育・環境・食・情報・伝統文化・経済）から選び、「原因／関係者／影響／解決策」の4視点で疑問の例をカード表示する。
  2. 別分野のレンズ選び（Y軸）：7つ（心理学・テクノロジー・ジェンダー・デザイン・言語・マスメディア・インフラ）から1つ選ぶ。
  3. 交差点まとめ画面：X軸とY軸を整理し、「交差点になりうる問い」の例を3つ表示する。
  4. 問いの洗練：5W1Hで具体化し、検索キーワードと調査方法のヒント（文献・アンケート・インタビュー）を示して終了。
- AIの振る舞いルール：親しみやすい丁寧語、肯定的、倫理的に問題のある方向や実現困難な方向は建設的に軌道修正、自然な日本語のみ。問いが完成したら実行支援には進まない。
- 選択肢はカード（ボタン）で選べる。番号入力は求めない。

**あれば便利**
- 完成した問いを画面からコピー／印刷できる。
- 同じ画面で「やり直し」ができる。

## 4. 画面の流れ
1. チャット画面で分野カードを選ぶ。
2. 4視点の疑問カードから選ぶ、または自分の疑問を入力。
3. レンズ（別分野のメガネ）を選ぶ。
4. 交差点まとめ画面で、整理と問いの例3つを確認。
5. チャットに戻り、5W1Hで問いを具体化して完成。

## 5. 扱うデータ
- 入力：選んだ分野・レンズ、生徒が自由に書いた疑問（テキスト）。
- AIの返答はJSONで受け取り、カード表示用に整える（例：`{ message, cards: [{ angle, text }], next }`）。
- 出力：画面表示のみ。会話履歴はサーバーに保存せず、交差点画面へ渡す一時データだけ sessionStorage に置く（ブラウザを閉じると消える）。

## 6. 個人情報の扱い
- **氏名・学年・クラスを入力させない**。AIに送るのは、選んだ分野・レンズと生徒が書いた探究の疑問だけ。
- 入力欄に「名前や個人が特定できる情報は書かない」と注意書きを出す。
- サーバーに会話を保存しない（ログに本文を残さない設定を推奨）。
- 生徒が個人的な悩みを書いてきた場合は、AIが探究の話題に戻すか、先生への相談を促す。

## 7. 技術の例
- 例：Next.js（App Router）＋TypeScript＋Tailwind CSS＋Vercel。
- AIは Gemini API の Flash 系モデルなど。**APIキーはサーバー側の環境変数に置き**、AIの呼び出しはサーバー側のAPIルートだけで行う。
- 1人あたりの回数制限や入力文字数の上限を付けて、従量課金の使いすぎを防ぐ。
- まず既存のAIチャット（カスタム指示機能）で試作し、うまくいってからアプリ化する進め方もよい。

## 8. AIに作らせるときのコツ
- ステップごとの進め方と「してはいけないこと（答えを教える・実行支援をする）」を、**システム指示として文章で先に固めて**から画面を作らせる。
- AIの返答のJSONの形を先に決め、画面表示とAI呼び出しを分けて作らせる。
- 実際に生徒役で試し、固定したい文言（締めのひとこと等）は画面側に持たせて、AIに毎回書かせない。
